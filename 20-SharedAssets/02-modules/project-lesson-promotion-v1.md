# 项目经验资产化机制 v1

## 目标

旧项目经验的价值不在于登记“做过什么”，而在于下一次 AI 开工前能被召回、能变成检查项、能减少重复试错。

## 经验价值链

```text
项目经历
  -> 经验速记
  -> 经验资产卡
  -> 项目桥接卡召回
  -> 开工必读 / 检查清单 / 模板
  -> 下一次任务使用
```

只停在交接卡或经验 INBOX，价值是“以后可能找得到”；进入桥接卡和检查清单，价值才会变成“开工前会用到”。

## 什么经验值得升舱

满足任一条，就应从交接卡或经验 INBOX 升舱：

| 标准 | 说明 |
|---|---|
| 第二次出现 | 同类问题已经重复出现，说明不是偶发 |
| 节省时间 | 下次照做可节省 15 分钟以上 |
| 避免返工 | 不提前检查会导致大改、误判或线上风险 |
| 可转动作 | 能写成命令、检查项、模板或判断口径 |
| 跨项目适用 | 不只服务某一次会话或某个临时环境 |

## 问题 / 事故强制复盘

出现以下任一情况，任务结束前必须判断是否需要写成问题事故经验：

| 触发 | 必须判断的问题 |
|---|---|
| 失败或返工 | 下次能否提前发现、提前验证或避免同样路径 |
| 测试失败或回归 | 是否缺少固定检查项、样例或验收口径 |
| 用户纠正 | AI 哪个假设错了，之后如何少猜 |
| 工具、插件、浏览器、代理、权限、性能异常 | 是否有稳定症状、排查顺序和禁止动作 |
| 配置损坏或误改 | 哪些文件不能直接手写，应该通过什么入口修改 |
| 同类问题第 2 次出现 | 必须从经验 INBOX 升舱为经验资产或检查清单 |

事故经验只记录可复用教训，不记录情绪、流水和完整聊天。

最小结论必须包含：

1. 触发条件：下次看到什么现象要想起这条经验。
2. 根因或稳定判断：确认了什么，不确定什么。
3. 处理动作：下一次照什么顺序做。
4. 验证方式：怎么判断问题真的解决。
5. 禁止事项：哪些动作会扩大损失或造成误判。

模板：`00-AI/templates/TPL-incident-experience-card.md`

## 什么不升舱

- 一次性环境状态。
- 未验证猜测。
- 完整聊天记录。
- 只解释当时过程、不能指导下次行动的流水。
- Cookie、Token、API Key、密码、验证码、身份证号、银行卡、私密联系方式。

## 经验资产卡最小字段

经验资产不追求长，必须能让下一位 AI 直接用：

| 字段 | 要回答的问题 |
|---|---|
| 适用场景 | 什么任务开始前要读它 |
| 触发条件 | 看到什么现象时要想起它 |
| 稳定结论 | 已验证的判断是什么 |
| 处理动作 | 下一次照什么做 |
| 验证方式 | 怎么知道处理有效 |
| 禁止事项 | 哪些做法容易误伤 |
| 来源链接 | 经验来自哪个项目、交接卡或文件 |
| 复用记录 | 是否已经被第二个任务用过 |

## 写入位置

| 经验类型 | 写入位置 |
|---|---|
| 跨项目规则、检查清单、SOP | `20-SharedAssets/02-modules/` |
| 反复踩坑的解决方案 | `20-SharedAssets/02-modules/` 或问题知识卡 / 经验资产卡 |
| 某个项目专属状态和边界 | 对应 项目桥接卡 |
| 某次任务的短期交接 | `01-Inbox/agent-handoffs/` |

## 桥接卡召回规则

重要项目桥接卡必须有“经验召回”段落，至少回答：

| 任务类型 | 应召回的经验 | 使用方式 |
|---|---|---|
| 开发任务 | 原型、测试、部署、数据迁移相关经验 | 开工前转成检查项 |
| 运维任务 | 代理、后台服务、系统性能、磁盘空间经验 | 先查稳定症状，再动手 |
| 交易任务 | 数据来源、策略准入、风控、回测偏差经验 | 先确认边界，再做实验 |
| 知识库任务 | Inbox、归档、桥接卡、经验升舱经验 | 只做能提升 AI 接手能力的改动 |

桥接卡不复制经验全文，只放“什么时候读哪条经验，以及读完要做什么”。

## 每周轻量动作

- 从经验 INBOX 只挑 3-5 条“复用=是”的条目。
- 每条判断：丢弃、保留速记、升舱成经验资产、挂到桥接卡。
- 先处理 P0 项目相关经验，再处理低频项目。
- 已升舱的条目，在来源处补链接，不重复写多份全文。
