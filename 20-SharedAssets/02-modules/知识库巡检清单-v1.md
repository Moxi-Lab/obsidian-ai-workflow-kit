# 知识库巡检清单 v1

用于做 Obsidian 知识库的轻量健康检查，重点不是“加更多目录”，而是保证**入口可信、链接可达、状态清楚、沉淀顺畅**。

## 一、入口可信化（每周至少一次）

- [ ] `index.md` 的主入口都能打开
- [ ] `KB-MANIFEST` 指向的权威状态源都能打开
- [ ] 3 个 context pack 都能打开，并且没有互相矛盾
- [ ] `02-主题地图MOCs/MOC-INDEX.md` 的四大主线都能打开
- [ ] 四大主线都存在 README / 主入口页
- [ ] MOC 中列出的目录与实际目录一致
- [ ] 首页、MOC、README 三者没有互相打架

## 二、断链与旧链接治理（每两周一次）

- [ ] 检查是否存在指向旧结构/旧命名的 wikilink
- [ ] 检查是否存在 basename 歧义链接
- [ ] 检查迁移残留（如 1.0 路径、旧项目代号、旧 Agent-OS 路径）
- [ ] 发现断链后，优先修“高频入口页”而不是边角文件

## 三、Inbox / 状态治理（每周一次）

- [ ] `01-收件箱Inbox/` 只承担分流，不承担长期堆积
- [ ] Agent交接卡是否有长期滞留在 `00-Inbox`
- [ ] 网页剪藏是否及时从 `00-Inbox` 转入 `01-已处理` 或 `99-异常`
- [ ] 新增内容是否有明确状态：`draft / active / waiting / archived`
- [ ] 处理完成的内容是否有明确去向（项目、共享资产、经验库、外部资料）

## 四、内容健康检查（每周一次）

- [ ] 检查是否存在同一主题的重复学习卡或重复剪藏
- [ ] 检查是否有旧结论被新资料推翻但未标注
- [ ] 检查是否有页面之间说法互相矛盾
- [ ] 检查是否有重要页面没有任何入站链接或关联入口
- [ ] 检查是否有反复出现的高频概念仍缺少权威页
- [ ] 检查近期高价值问答是否已回写到项目、共享资产或经验库

## 五、项目层健康度（每两周一次）

- [ ] 每条主线都有“当前定位”说明：强主线 / 弱主线 / 孵化中
- [ ] README 中写清楚当前重点、常用入口、下一步动作
- [ ] 空主线要么降级为孵化，要么补最小骨架，不允许首页强推但内部空壳
- [ ] 项目内可复用内容是否上浮到 `20-共享资产SharedAssets/`

## 六、元数据最小标准（持续）

新增页面必须遵守 [元数据最小标准-v1](./元数据最小标准-v1.md)。

最小 frontmatter：

```yaml
---
type:
created:
updated:
status:
pillar:
---
```

按类型再补充可选字段：

- 项目页：`owner` `stage` `priority`
- 交接卡：`source_agent` `handoff_type` `next_action`
- 外部资料：`source` `author` `captured` `related_project` `related_moc` `related_notes`

## 七、Agent 可调用性检查（每周一次）

- [ ] 高频任务是否已有 context pack
- [ ] 新增规则是否已接入 `KB-MANIFEST`
- [ ] 权威状态源是否少于 10 个，避免入口膨胀
- [ ] 旧交接卡、旧剪藏、旧目标是否没有覆盖当前状态页
- [ ] LLM-Wiki-Lab 输出仍保持人工审核后再回写

## 八、推荐处理优先级

1. 先修首页 / MOC / README 等高频入口
2. 再修 `KB-MANIFEST` 和 context pack
3. 再修断链与旧链接
4. 再清 Inbox 与状态字段
5. 再查重复、矛盾、过时和孤立内容
6. 再补元数据和复用资产上浮
7. 最后才考虑继续扩目录

## 九、使用口令（可直接复制）

```text
按《知识库巡检清单 v1》执行一轮巡检：
1) 先检查 index / MOC-INDEX / 四大主线 README 是否可达；
2) 列出断链、旧链接、过时 MOC；
3) 标出 Inbox 堆积点；
4) 标出重复、矛盾、过时、孤立内容；
5) 标出空主线、弱主线；
6) 只优先修高频入口，不要一上来全库大改。
```
